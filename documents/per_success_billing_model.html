🎯 Pay-Per-Success Model: Charge only when a user successfully completes an action using your service. Failed attempts are free. This aligns your revenue with customer value.
What Counts as "Success"?

✅ Passport Usage

User successfully authenticates/verifies passport data. Status = success, no errors thrown.

✅ Trial/Log Completion

User completes a task, trial period, or log request. Returns 200/201 response code.

✅ Data Processing

Successfully processed and stored data. Not when validation fails or data rejected.

✅ Any Service Action

Whatever your core service does — if it works, user pays. If it fails, it's free (troubleshooting).

Pricing Model Examples
Option A: Flat Per-Success
Passport Verification: $0.10 per success Trial Completion: $0.15 per success Log Entry: $0.05 per success Customer usage in May: - 5,000 successful passports - 1,200 trials completed - 18,000 log entries Charge = (5000 × $0.10) + (1200 × $0.15) + (18000 × $0.05) = $500 + $180 + $900 = $1,580/month
Option B: Tiered + Per-Success
Starter: $49/mo → 500 free successes included Pro: $149/mo → 5,000 free successes included Enterprise: Custom pricing + $0.05 per success beyond included limit Customer on Pro: - Uses 8,000 successful passports - Charge = $149 + (3000 overage × $0.05) - Total = $149 + $150 = $299/month

How to Track Successful Events
Database Schema for Tracking
Table: successful_events - id (uuid) - user_id (references users) - org_id (references organizations) - event_type (passport, trial, log_entry, etc.) - success_status (success, failed, pending) - timestamp (when it happened) - amount_charged (how much to bill for this) - billing_cycle (which month's invoice) - invoice_id (once billed) Table: event_charges - event_id (references successful_events) - charge_amount ($) - charge_date - refunded (boolean) - refund_reason (if applicable)
When to Record Success
1
User calls your API endpoint
POST /api/passport/verify with user data
2
Validate & process
Run your business logic (verify passport, process trial, log data)
3
Check result
Did it succeed? (status 200/201, no business logic errors)
4
If SUCCESS: Record event
Log to successful_events table with amount_charged = $0.10 (or whatever your rate is)
5
If FAILED: No charge
Log to event logs for troubleshooting, but don't create a charge record
6
Monthly: Aggregate & bill
Sum all successful_events for the month, create invoice, charge Stripe
Code Example: Recording Success
// POST /api/passport/verify async function verifyPassport(req, res) { const { userId, passportData } = req.body; try { // 1. Validate and process const result = await validatePassport(passportData); if (!result.isValid) { // Failed - no charge return res.status(400).json({ error: 'Invalid passport', charged: false }); } // 2. Success! Record the charge await db.insert('successful_events', { user_id: userId, org_id: req.org.id, event_type: 'passport_verification', success_status: 'success', timestamp: new Date(), amount_charged: 0.10, // Your rate billing_cycle: getCurrentBillingCycle() }); // 3. Return success with info return res.status(200).json({ success: true, data: result, charged: true, chargeAmount: 0.10, message: 'Passport verified & charged' }); } catch (error) { // Error - no charge res.status(500).json({ error: error.message, charged: false }); } }
💡 Key insight: Record success BEFORE returning response. This way if your API returns an error (validation failed, data rejected), it's automatically not charged. Only successful completions hit the database.
Monthly Billing Process
Step 1: Aggregate Successful Events
-- At end of month, count all successes per user SELECT user_id, org_id, event_type, COUNT(*) as success_count, SUM(amount_charged) as total_due FROM successful_events WHERE billing_cycle = 'May 2024' AND success_status = 'success' GROUP BY user_id, org_id, event_type
Step 2: Apply Pricing Tier Logic

If using tiered model (included successes + overage):

-- User on Pro plan ($149/mo, 5K included) SELECT org_id, 'passport' as event_type, COUNT(*) as total_successes, GREATEST(0, COUNT(*) - 5000) as overage_count, GREATEST(0, COUNT(*) - 5000) * 0.05 as overage_charge FROM successful_events WHERE org_id = 'org_123' AND billing_cycle = 'May'
Step 3: Calculate Invoice Total
-- Example invoice for May Invoice for user@example.com (Org ABC) Base Plan (Pro) $149.00 ├─ Passport verifications: 8,000 used (5K included, 3K overage) │ Overage charge: 3,000 × $0.05 = $150.00 ├─ Trial completions: 500 used (included) └─ Log entries: 12,000 used (included) Total Due $299.00
Step 4: Charge via Stripe
// Monthly billing job (runs on 1st of month) async function createMonthlyInvoices() { const orgs = await db.query(` SELECT org_id, SUM(amount_charged) as total FROM successful_events WHERE billing_cycle = 'May 2024' GROUP BY org_id `); for (const org of orgs) { const invoice = await stripe.invoices.create({ customer: org.stripe_customer_id, auto_advance: true, metadata: { org_id: org.id, billing_cycle: 'May 2024' } }); // Add line item await stripe.invoiceItems.create({ customer: org.stripe_customer_id, invoice: invoice.id, amount: Math.round(org.total * 100), // Convert to cents currency: 'usd', description: 'API usage charges - May 2024' }); // Finalize & send await stripe.invoices.finalizeInvoice(invoice.id); } }
⚠️ Idempotency: Make sure your billing job can run multiple times without double-charging. Mark successful_events as billed after creating invoice to prevent re-processing.
System Components

🔴 API Service (Your existing code)

When API call succeeds, insert into successful_events table. That's it.

📊 Event Logger

Tracks all successful events. Fast writes (insert only, no reads during request).

💰 Billing Engine

Monthly job that aggregates events, applies tier logic, creates Stripe invoices.

📈 Analytics Dashboard

Real-time view of successes, revenue, per-user usage. For customer dashboard.

Recommended Tech Stack
Component Technology Why
Event Recording PostgreSQL (write-optimized partition by month) Simple INSERT, massive scale. Partition by billing_cycle for fast queries.
Real-time Counters Redis (optional but recommended) Fast counter increments for dashboard. Sync to PostgreSQL hourly.
Monthly Billing Job Node.js + Bull Queue Async job runner. Scheduled for 1st of month. Can retry if Stripe fails.
Payment Processing Stripe Invoicing API Handles recurring, invoices, webhooks, retries.
Customer Dashboard React (you already have this) Show usage breakdown by event type. Real-time meter. Estimated bill.
Admin Dashboard React admin panel View all events, adjust charges, issue refunds, view revenue.
